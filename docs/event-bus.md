# Badger EventBus

Lightweight, dependency-free, strongly typed publish/subscribe bus for Badger
lifecycle observability. It is **not** part of the tunnel WebSocket protocol.

## Architecture

```text
Composition root (EventModule / createEventBus)
        │
        │ inject EVENT_BUS
        ▼
   InMemoryEventBus
        │
   publish(type, payload) ──▶ typed handlers (subscribe / once)
```

- **Zero impact on tunnels:** subscriber errors are isolated; publishers never
  await handlers.
- **DI-first:** Nest provides `EVENT_BUS` via `EventModule`. Manual composition
  uses `createEventBus()`.
- **Immutable payloads:** build with `createEventPayload()` (frozen objects).

Layer 1 forwarding modules do not publish yet. They may inject `EVENT_BUS` later
without changing protocol semantics.

## Public API

```ts
import {
  BadgerEventType,
  createEventBus,
  createEventPayload,
  EVENT_BUS,
} from "@hridhin-k/badger-shared";

const bus = createEventBus();

const payload = createEventPayload({
  tunnelId: "tun-1",
  publicUrl: "https://tun-1.example",
  port: 3000,
  restored: false,
  correlationId: "tun-1",
});

bus.subscribe(BadgerEventType.TunnelCreated, (event) => {
  console.log(event.eventId, event.occurredAt, event.tunnelId);
});

bus.once(BadgerEventType.TunnelClosed, (event) => {
  console.log("closed once", event.reason);
});

bus.publish(BadgerEventType.TunnelCreated, payload);

bus.unsubscribe(BadgerEventType.TunnelCreated, handler);
```

### Methods

| Method                       | Behavior                                                          |
| ---------------------------- | ----------------------------------------------------------------- |
| `publish(type, payload)`     | Deliver to current subscribers; never throws for handler failures |
| `subscribe(type, handler)`   | Register; returns `{ unsubscribe() }`                             |
| `unsubscribe(type, handler)` | Remove by exact handler reference                                 |
| `once(type, handler)`        | Deliver at most once, then auto-remove                            |
| `clear()`                    | Drop all subscriptions                                            |

### Event base fields

Every payload includes:

- `eventId` — unique id (UUID when generated by `createEventPayload`)
- `occurredAt` — epoch ms timestamp
- `correlationId` — optional flow id (`requestId`, connection id, etc.)
- `tunnelId` — on tunnel/request events where applicable

### Event types

`TunnelCreated`, `TunnelClosed`, `ClientConnected`, `ClientDisconnected`,
`RequestReceived`, `RequestForwarded`, `ResponseReturned`, `RequestFailed`,
`ReconnectStarted`, `ReconnectSucceeded`.

`RequestReceived` includes `headers`, `query`, and a truncated `body`
snapshot. `ResponseReturned` includes `responseHeaders`, `responseBody`, and
`latencyMs`. See [docs/traffic-recorder.md](traffic-recorder.md).

## NestJS integration

`AppModule` imports `EventModule`, which exports `EVENT_BUS`:

```ts
import { Inject, Injectable } from "@nestjs/common";
import {
  EVENT_BUS,
  type EventBus,
  BadgerEventType,
  createEventPayload,
} from "@hridhin-k/badger-shared";

@Injectable()
export class ExampleSubscriber {
  constructor(@Inject(EVENT_BUS) private readonly eventBus: EventBus) {
    this.eventBus.subscribe(BadgerEventType.TunnelCreated, (e) => {
      // observability only
    });
  }
}
```

## Rules

- No external libraries in the bus implementation (Node `crypto.randomUUID` only).
- Do not change tunnel protocol messages to carry these events.
- Do not block the forward path on subscribers.
